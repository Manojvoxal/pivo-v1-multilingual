# Voxal Studio: text to speech in 12 Indian languages, in the browser

A web page where anyone can type in **Kannada, English, Hindi, Telugu, Tamil, Bengali, Marathi,
Gujarati, Punjabi, Malayalam, Odia or Assamese** and hear it spoken by the multilingual PiVo model
(PiVo-Multi-1.8M: 24 voices, a female and a male voice per language). Two drop-downs above the
text box (mirrored under Settings) pick the **language** and the **voice**. The model runs **in the
visitor's browser, on their own CPU** (ONNX Runtime Web, WebAssembly). The server only hands out
static files: no GPU, no inference server, and text and audio never leave the visitor's computer.

```
visitor's browser                                   Modal (or any static host)
┌───────────────────────────────────────────┐       ┌────────────────────────┐
│ page (main.js) ── text, lang, voice ─▶     │ ◀──── │ HTML/JS, 4 ONNX files, │
│   ▲                Web Worker             │ once  │ ORT wasm, dictionary   │
│   │                frontend_multi.js (G2P)│       └────────────────────────┘
│   │                engine.js (ONNX, WASM) │
│   └── PCM blocks ◀─┘                       │
│ player.js (plays while generating) → WAV   │
└───────────────────────────────────────────┘
```

| | |
|---|---|
| **First visit** | about 10 MB download (model 6.9 MB + runtime 3 MB, gzip), then cached by the browser |
| **Speed** | about 4–5× faster than real time in headless Chromium on a small cloud CPU; audio starts while the rest is generated |
| **Same model** | the exact exported ONNX graphs (`models/multi_w128_refine/onnx`); browser audio matches an independent Python ONNX Runtime run on all 24 voices (same length; a few frames may differ slightly from float rounding in the recurrent vocoder) |
| **Same text rules** | `app/frontend_multi.js` is a line-by-line port of `training/data_pipeline_multi/pivo_multi`; identical token ids on the 1,636 validation sentences and on ~50k random words / ~17k random sentences in every script |
| **Browsers** | recent Chrome, Edge, Firefox, Safari 16.4+ (desktop and phone) |

## Run it on your PC

```bash
pip install uvicorn
python web/build.py          # gathers everything into web/dist (downloads ONNX Runtime Web once)
python web/server.py         # open http://localhost:8000
```

`build.py` reads the model from `models/multi_w128_refine/onnx` (made by
`modal run training/train_gpu.py --stage export` + `modal volume get`); pass `--model-dir` for another export.

## Deploy on Modal

```bash
python web/build.py
modal deploy web/modal_app.py
```

The app is called **`voxal-studio-multi`**, so it gets its own URL
(`https://<workspace>--voxal-studio-multi.modal.run`) and the existing Kannada + English site
(`voxal-studio`, from pivo-v1) keeps running. One small CPU container (0.5 CPU, 512 MB) that sleeps
when nobody visits; `VOXAL_MIN_CONTAINERS=1 modal deploy web/modal_app.py` keeps one warm.

Re-run both commands after any change to `web/app/` or the model.

## Files

| file | what it does |
|---|---|
| `app/index.html`, `app/styles.css` | page layout, language + voice drop-downs, Voxal theme, Noto fonts for all scripts |
| `app/main.js` | text box, language / voice drop-downs, language hint, status, generate / stop, waveform, download |
| `app/worker.js` | Web Worker: downloads the model with progress, phonemizes, splits text into sentences, streams audio |
| `app/engine.js` | encoder (tokens, voice, **lang**) → durations → decoder → FARGAN vocoder |
| `app/frontend_multi.js` | the 12-language frontend: Brahmic G2P (9 scripts), English via CMU, number reading |
| `app/numbers_multi.js`, `app/numwords.js` | numbers, dates, times, money, units and symbols for hi mr gu pa bn or as ta te ml (port of `pivo_multi/numnorm.py`; `numwords.js` is generated by `build.py` from `numwords.json`) |
| `app/semiotic.js`, `app/semiotic_words.js` | first pass for all 12 languages: telephones, times, dates, money, units, fractions, math, e-mail / URLs, serial codes, roman numerals, abbreviations (port of `pivo_multi/semiotic.py`; `semiotic_words.js` is generated from `semiotic.json`) |
| `app/frontend.js` | shared helpers from PiVo-KN: English and Kannada number normalisers, CMU lexicon, sentence splitting |
| `app/player.js` | plays audio while it is generated; pause, seek, WAV export |
| `build.py` | builds `dist/`: checks the model, pins ONNX Runtime Web 1.20.1 by SHA-256, gzip copies, manifest |
| `server.py` | dependency-free static server (gzip, ETag, long caching for hashed files, CSP) |
| `modal_app.py` | Modal deployment of `server.py` + `dist/` |
| `tests/parity_multi_ref.py`, `tests/parity_multi.mjs` | frontend parity: Python vs JavaScript |
| `tests/numbers_parity_ref.py`, `tests/numbers_parity.mjs` | number normaliser parity: Python vs JavaScript (~150k cases) |
| `tests/e2e_multi.py`, `tests/chunks_multi.mjs` | real-browser test: every language and voice via the drop-downs vs Python ONNX Runtime |

## How the page handles text

- **Write in the language's own script.** If the text is in another script (or is English while an
  Indian language is selected), the page suggests switching.
- **English words** inside Indian-language text use the CMU dictionary (fetched in the background);
  words not in it are read with Indian spelling rules and listed under "How it was read".
- **Numbers** are read in the language itself, formal / news style. Kannada keeps PiVo's Kannada
  reader and English the Indian-English one; the other ten languages use `numbers_multi.js`:
  lakh/crore grouping, decimals, negatives, native digits (०-९ ০-৯ ੦-੯ ૦-૯ ୦-୯ ௦-௯ ౦-౯ ൦-൯), dates
  with month names, years ("उन्नीस सौ सैंतालीस", "উনিশশো একাত্তর"), times with morning / evening
  words, ₹ / Rs / $ / € / £ with lakh / crore, %, ranges, units, phone numbers and PIN codes digit by
  digit, ordinals (21वीं, ৫ম, ১লা বৈশাখ, 5ஆம், 5వ, 5-ാം), suffixes glued to numbers with the right
  sandhi (2026లో, 2026இல், 2026-ൽ, ২০২৬-এ), acronyms spelled in the language's script (BJP → बी जे पी)
  and symbols. Before that, `semiotic.js` reads telephone numbers in groups ("Call 020 7946 0018"),
  times in any spelling (6:15PM, 6.15 pm, 10:30:45, 9am-5pm), dates (2024/08/15, Aug 15, 2024),
  fractions, math, units such as °F / m² / kWh / MP, e-mail and web addresses, serial codes and
  roman numerals, in all 12 languages. The words are in `training/data_pipeline_multi/pivo_multi/numwords.json`; see
  `NUMBER_REVIEW.xlsx` there for every choice that a native speaker should confirm.
- **Long text** is read sentence by sentence (then at commas, then between words).
- **Emoji and unsupported symbols** are skipped and listed on the page.

## Tests

```bash
# text frontend: JavaScript must give the same token ids as Python (add the val manifest for real text)
python web/tests/parity_multi_ref.py ref.json --cmudict src/pivo/resources/cmudict.dict \
    --manifest training/data_pipeline_multi/val.jsonl
node web/tests/parity_multi.mjs ref.json web/dist/lexicon/cmudict.txt

# whole site in Chromium (pip install playwright uvicorn onnxruntime && playwright install chromium)
python web/tests/e2e_multi.py --model-dir models/multi_w128_refine/onnx --both-voices

# number normaliser: JavaScript must give the same text as Python
python web/tests/numbers_parity_ref.py numref.json
node web/tests/numbers_parity.mjs numref.json
```

If you change a G2P rule in `training/data_pipeline_multi/pivo_multi/`, make the same change in
`app/frontend_multi.js`, rerun the parity test, and retrain (the model learned the old rule).
Number words need no retraining: edit `numwords.json` (the build copies it into `app/numwords.js`);
a rule change in `numnorm.py` needs the same change in `app/numbers_multi.js` and both parity tests;
a change in `semiotic.py` needs the same change in `app/semiotic.js` (copy it to `src/pivo/` too).
